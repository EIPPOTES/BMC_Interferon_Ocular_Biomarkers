## 第一部分: 研究伦理与规范

### 1. 赫尔辛基宣言 (Declaration of Helsinki)

**概述**:
- 由世界医学协会 (WMA) 于1964年制定
- 人体实验伦理的基石文件
- 虽非国际法律，但影响各国法规
- 对医生具有道德约束力

**基本原则**:

#### 1.1 尊重个人 (Respect for the Individual)
- **自主决定权**: 个人有权自我决定
- **知情同意**: 参与研究前必须知情同意 (Articles 20, 21, 22)
- **弱势群体保护**: 对无能力者、未成年人需特别保护 (Articles 23, 24, 25)

#### 1.2 有利原则 (Beneficence)
- **患者福祉优先**: 参与者福祉优先于科学和社会利益 (Article 5)
- **风险-受益评估**: 仔细评估风险和受益 (Articles 16, 17)
- **研究者责任**: 研究者仅对患者或志愿者负责 (Articles 2, 3, 10)

#### 1.3 公正原则 (Justice)
- **公平选择**: 公平选择研究参与者
- **负担和受益公平分配**: 避免剥削弱势群体
- **全球健康**: 关注全球健康需求

**操作原则**:
- 研究基于充分的科学背景知识 (Article 11)
- 由受过适当培训的研究者进行 (Article 15)
- 使用批准的方案，接受独立伦理审查 (Article 13)
- 符合 Declaration 的伦理要求 (Article 14)

**眼科研究特殊考虑**:
- 视力损害患者的知情同意
- 安慰剂对照的伦理考量
- 基因研究的遗传咨询义务
- 儿童眼科研究的特殊保护

### 2. 伦理审查流程

#### 2.1 伦理委员会 (IRB/EC)

**定义**:
- IRB (Institutional Review Board): 美国常用
- EC (Ethics Committee): 欧洲常用
- REC (Research Ethics Committee): 英国常用

**组成**:
- 至少5名成员
- 不同专业背景 (医学、法律、伦理、社区代表)
- 性别平衡
- 至少一名非机构成员

**审查类型**:

| 审查类型 | 适用情况 | 时间 |
|---------|---------|------|
| **会议审查** | 大多数研究 | 1-2月 |
| **快速审查** | 最小风险研究 | 2-4周 |
| **豁免审查** | 特定类别 (如公开数据) | 1-2周 |

#### 2.2 伦理审查内容

**科学审查**:
- 研究设计是否合理?
- 样本量是否充足?
- 统计方法是否适当?

**伦理审查**:
- 风险-受益比是否合理?
- 知情同意是否充分?
- 隐私保护措施是否到位?
- 弱势群体是否得到额外保护?

#### 2.3 中国伦理审查流程

**步骤**:
1. **准备材料**:
   - 研究方案
   - 知情同意书
   - 研究者简历
   - 病例报告表
   - 招募广告

2. **提交申请**:
   - 机构伦理委员会
   - 医院伦理委员会
   - 大学伦理委员会

3. **审查过程**:
   - 形式审查 (完整性)
   - 实质审查 (科学性、伦理性)
   - 会议讨论
   - 投票决定

4. **审查结果**:
   - 批准
   - 修改后批准
   - 修改后再审
   - 不批准

5. **持续审查**:
   - 年度进展报告
   - 严重不良事件报告
   - 方案修改申请
   - 结题报告

### 3. 知情同意书撰写

#### 3.1 知情同意的要素

**四个核心要素**:
1. **选择能力 (Choice)**: 能够做出决定
2. **理解能力 (Understanding)**: 理解相关事实
3. **欣赏能力 (Appreciation)**: 认识到事实对自己的影响
4. **推理能力 (Reasoning)**: 能够进行逻辑推理

#### 3.2 知情同意书内容

**必需内容**:
```
1. 研究目的和背景
2. 研究程序 (做什么、多久、多少次)
3. 潜在风险和不适
4. 潜在受益
5. 替代治疗选择
6. 保密措施
7. 补偿和赔偿
8. 自愿参与和随时退出权
9. 联系人信息
10. 知情同意声明和签名
```

#### 3.3 眼科研究特殊考虑

**视力损害患者**:
- 使用大字体 (≥14pt)
- 提供音频版本
- 允许家属协助阅读
- 确保真正理解

**侵入性操作** (如玻璃体腔注射):
- 详细说明操作过程
- 说明可能的并发症
- 术后注意事项
- 紧急联系方式

**基因研究**:
- 说明基因信息的敏感性
- 说明是否会告知结果
- 说明数据共享范围
- 遗传咨询安排

### 4. 数据隐私保护

#### 4.1 法规框架

**国际**:
- GDPR (欧盟通用数据保护条例)
- HIPAA (美国健康保险流通与责任法案)

**中国**:
- 《个人信息保护法》
- 《数据安全法》
- 《人类遗传资源管理条例》

#### 4.2 数据保护措施

**数据收集阶段**:
- 最小必要原则
- 明确告知用途
- 获得明确同意

**数据存储阶段**:
- 加密存储
- 访问控制
- 定期备份
- 去标识化

**数据共享阶段**:
- 再次获得同意
- 数据使用协议
- 限制访问范围

**数据销毁阶段**:
- 按约定时间销毁
- 安全删除
- 销毁证明

#### 4.3 去标识化方法

| 方法 | 说明 | 适用 |
|------|------|------|
| **匿名化** | 永久去除标识符 | 公开数据集 |
| **假名化** | 用代码替代标识符 | 研究数据库 |
| **k-匿名** | 确保k条记录相同 | 高敏感数据 |

#### 4.4 眼科数据特殊保护

**影像数据**:
- 去除面部特征
- 仅保留眼部区域
- 删除DICOM中的患者信息

**基因数据**:
- 严格控制访问
- 单独存储标识符
- 限制数据共享

## 第二部分: 批判性思维与循证医学

### 1. 批判性思维

**定义**: 分析事实、证据、观察和论据，以形成合理判断的过程

**核心能力**:
- 质疑假设
- 评估证据质量
- 识别逻辑谬误
- 多角度思考
- 自我纠正

#### 1.1 文献批判性阅读框架

**PICOS框架**:
- **P**opulation: 研究对象是谁?
- **I**ntervention: 干预是什么?
- **C**omparison: 对照是什么?
- **O**utcome: 结局指标是什么?
- **S**tudy design: 研究设计是什么?

**批判性检查清单**:
```
研究问题:
□ 研究问题是否明确?
□ 是否具有临床意义?
□ 是否可回答?

研究设计:
□ 设计是否适合研究问题?
□ 是否有更好的设计?
□ 对照是否适当?

样本:
□ 样本量是否充足?
□ 抽样方法是否适当?
□ 代表性如何?
□ 失访率是否可接受?

测量:
□ 测量工具是否可靠?
□ 是否盲法评估?
□ 是否有测量偏倚?

统计分析:
□ 统计方法是否正确?
□ 是否控制了混杂?
□ 多重比较是否校正?
□ 缺失数据处理是否适当?

结果:
□ 结果是否清晰呈现?
□ 效应量是否报告?
□ 置信区间是否提供?

讨论:
□ 解释是否合理?
□ 是否过度推断?
□ 局限性是否诚实报告?
□ 与既往研究比较是否准确?
```

#### 1.2 常见逻辑谬误

| 谬误 | 说明 | 示例 |
|------|------|------|
| **选择性报告** | 只报告阳性结果 | 多次分析只报告P<0.05的 |
| **幸存者偏倚** | 只分析存活者 | 只分析完成研究的患者 |
| **混杂偏倚** | 第三方因素影响 | 年龄影响疾病和暴露 |
| **因果倒置** | 颠倒因果关系 | 疾病导致暴露而非相反 |
| **生态学谬误** | 群体结论推个体 | 国家水平数据推个人 |

### 2. 循证医学 (Evidence-Based Medicine, EBM)

**定义**: 慎重、准确和明智地应用当前最佳证据，同时结合临床专业技能和患者价值观，做出医疗决策

**三要素**:
1. **最佳研究证据**
2. **临床专业技能**
3. **患者价值观**

#### 2.1 证据等级金字塔

```
        系统综述/Meta分析
               ↑
          RCT
               ↑
        队列研究
               ↑
      病例对照研究
               ↑
       病例系列
               ↑
        专家意见
```

#### 2.2 GRADE证据质量分级

| 级别 | 含义 | 说明 |
|------|------|------|
| **高** | 非常确信 | RCT或高质量观察性研究 |
| **中** | 中等确信 | 有局限性的RCT |
| **低** | 有限确信 | 有严重局限性的RCT或观察性研究 |
| **极低** | 非常不确定 | 有极严重局限性的观察性研究 |

**降级因素**:
- 研究局限性 (偏倚风险)
- 不一致性
- 间接性
- 不精确性
- 发表偏倚

**升级因素**:
- 大效应量
- 剂量-反应关系
- 残余混杂可能降低效应

#### 2.3 循证医学实践步骤

**5A步骤**:
1. **Ask**: 提出可回答的临床问题
2. **Acquire**: 寻找最佳证据
3. **Appraise**: 批判性评价证据
4. **Apply**: 应用证据于患者
5. **Assess**: 评估效果

#### 2.4 PICO问题构建

| 要素 | 说明 | 示例 |
|------|------|------|
| **P**atient/Population | 患者特征 | 糖尿病黄斑水肿患者 |
| **I**ntervention | 干预 | 抗VEGF治疗 |
| **C**omparison | 对照 | 激光治疗 |
| **O**utcome | 结局 | 视力改善 |

**示例问题**:
"在糖尿病黄斑水肿患者中，抗VEGF治疗与激光治疗相比，是否能更好地改善视力?"

## 第三部分: 数据管理与FAIR原则

### 1. FAIR数据原则

**定义**: 数据应可发现 (Findable)、可获取 (Accessible)、可互操作 (Interoperable)、可重用 (Reusable)

#### 1.1 可发现 (Findable)

**F1**: (元)数据被分配全局唯一且持久的标识符
- 使用DOI
- 使用ORCID

**F2**: 数据用丰富的元数据描述
- 详细的数据字典
- 变量说明
- 数据收集方法

**F3**: 元数据明确包含所描述数据的标识符

**F4**: (元)数据在可搜索的资源中注册或索引
- 上传到数据仓库
- 建立数据目录

#### 1.2 可获取 (Accessible)

**A1**: (元)数据可通过标准化通信协议获取
- HTTP/HTTPS
- API接口

**A1.1**: 协议开放、免费、可普遍实施

**A1.2**: 协议允许身份验证和授权

**A2**: 即使数据不再可用，元数据仍可获取

#### 1.3 可互操作 (Interoperable)

**I1**: (元)数据使用正式的、可访问的、共享的和广泛适用的语言表示知识
- 使用标准数据格式 (CSV, JSON)
- 使用标准词汇表

**I2**: (元)数据使用遵循FAIR原则的词汇表

**I3**: (元)数据包含对其他(元)数据的合格引用
- 引用相关数据集
- 引用方法论文献

#### 1.4 可重用 (Reusable)

**R1**: (元)数据用多个准确且相关的属性充分描述
- 数据收集时间
- 数据收集地点
- 数据收集方法
- 数据质量控制

**R1.1**: (元)数据发布时附带清晰且可访问的数据使用许可证
- CC0 (公共领域)
- CC-BY (署名)
- 自定义许可

**R1.2**: (元)数据附带详细的出处信息
- 数据来源
- 数据处理历史
- 版本信息

**R1.3**: (元)数据符合领域相关标准

### 2. 数据备份策略

#### 2.1 3-2-1备份规则

- **3**: 至少3份数据副本
- **2**: 使用2种不同存储介质
- **1**: 至少1份异地备份

#### 2.2 备份方案示例

```
原始数据 (工作电脑)
    ↓
本地备份 (外接硬盘)
    ↓
网络备份 (机构服务器)
    ↓
云备份 (OneDrive/Dropbox)
```

#### 2.3 备份频率

| 数据类型 | 备份频率 | 保留策略 |
|---------|---------|---------|
| 原始数据 | 实时同步 | 永久保留 |
| 分析数据 | 每日 | 保留1年 |
| 代码 | 每次修改 | 版本控制 |
| 文档 | 每日 | 保留3年 |

### 4. 代码版本控制 (Git)

#### 4.1 Git基础概念

**仓库 (Repository)**: 存储代码和版本历史的地方
**提交 (Commit)**: 保存代码的快照
**分支 (Branch)**: 独立的开发线
**合并 (Merge)**: 将分支合并到主线

#### 4.2 常用Git命令

```bash
# 初始化仓库
git init

# 添加文件到暂存区
git add filename
git add .  # 添加所有文件

# 提交更改
git commit -m "提交说明"

# 查看状态
git status

# 查看历史
git log

# 创建分支
git branch branchname

# 切换分支
git checkout branchname

# 合并分支
git merge branchname

# 推送到远程
git push origin main

# 从远程拉取
git pull origin main
```

#### 4.3 Git工作流程

```
工作目录 → git add → 暂存区 → git commit → 本地仓库 → git push → 远程仓库
```

#### 4.4 Git在科研中的应用

**代码管理**:
- R/Python分析脚本
- 数据清洗代码
- 可视化代码

**文档管理**:

- 研究笔记
- 会议记录

**协作**:
- 多人协作写作
- 代码审查
- 版本回溯

**创建仓库**:
