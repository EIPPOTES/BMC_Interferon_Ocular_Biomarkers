### 技能开发核心原则

#### 1. 简洁至上 (Concise is Key)
- 上下文窗口是公共资源
- 挑战每个段落的token成本
- 代码优先于描述

#### 2. 渐进式加载 (Progressive Disclosure)
```
Level 1: Metadata (name + description) - 始终在上下文 (~100词)
Level 2: SKILL.md body - 技能触发时加载 (<5k词)
Level 3: Bundled resources - 需要时加载 (无限制)
```

#### 3. 自由度匹配
| 场景 | 自由度 | 实现方式 |
|------|--------|----------|
| 多种方法都可行 | 高 | 文字描述工作流程 |
| 有推荐模式但有变化 | 中 | 伪代码或参数化脚本 |
| 操作脆弱/需一致性 | 低 | 特定脚本，少量参数 |

### 技能文件结构标准
```
skill-name/
├── SKILL.md              # 必需：技能定义
├── scripts/              # 可选：可执行脚本
├── references/           # 可选：参考文档
└── assets/               # 可选：模板和资源
```

### SKILL.md 标准格式
```yaml
---
name: skill-name
version: 1.0.0
description: "功能描述。使用此技能当用户需要：(1) 功能A (2) 功能B"
---

# 快速开始
...

## 高级用法
- **场景X**: 参见 [ADVANCED.md](references/ADVANCED.md)
```
